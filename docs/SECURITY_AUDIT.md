# Аудит безопасности GRAM City — октябрь 2026

Проверено автоматически (bandit, pip-audit, npm audit, обход всех маршрутов) и вручную.

## Итог
Критичных открытых дыр не осталось. Найдено и исправлено 4 серьёзных проблемы; ниже — что проверено и как.

## Исправлено
| # | Проблема | Риск | Что сделано |
|---|---|---|---|
| 1 | MongoDB без пароля (docker-compose) | любой процесс во внутренней сети читал и менял базу | пароль root + отдельный пользователь игры только на базу игры; база во внутренней сети Docker без выхода наружу |
| 2 | Токены нельзя было отозвать (сверка сессии намеренно выключена, токен живёт 30 дней) | украденный токен работал и после смены пароля | `iat` в каждом токене + `users.tokens_valid_after`; один слой перед всеми `/api` и проверка в WebSocket чата; отзыв при смене/сбросе пароля, «Выйти на всех устройствах», отключении 2FA. Несколько устройств одновременно по-прежнему можно |
| 3 | `python-jose` импортировался в 9 файлах, но отсутствовал в `requirements.txt` (и имеет неисправленные CVE) | сервер в чистом Docker-образе не запустился бы | все 9 файлов переведены на PyJWT; проверено запуском без `python-jose` |
| 4 | `/api/trade/spot` (прямая сделка) — одна сторона могла списать деньги с баланса другой | кража баланса | адрес отключён (410), торговля через рынок |

Ранее в этой же работе: 2FA при одобрении выплаты в боте; поиск пользователя по id в выплатах; шифрование личных данных; зашифрованные резервные копии.

## Проверено — проблем нет
- **Права админки.** 623 маршрута, из них 243 `/api/admin/*`: у всех, кроме шести, в цепочке есть проверка админа. Шесть — безопасны: публичный статус техработ; служебный `seed-test-users` (секрет в заголовке, выключен при `ENV=production`); четыре ловушки (`db-dump`, `backup-download`, `users/export.csv`, `secrets`) — данных не отдают, пишут тревогу в лог. Вживую 88 GET-адресов: без токена 401, с токеном игрока 403.
- **Чужие объекты (IDOR).** Все изменяющие действия с id в адресе проверяют владельца (контракты, предложения, лоты, аренда; `sys-ops` — только поддержка, с журналом).
- **Код бэкенда (bandit, medium+).** 7 мест, все безобидны: MD5 для цвета аватарки, SHA-1 для ключа кеша переводов, `0.0.0.0` внутри контейнера, временная папка.
- **Зависимости Python (pip-audit).** 148 пакетов — известных уязвимостей нет.
- **Зависимости фронтенда (npm audit).** 100 находок — все в инструментах сборки (react-scripts, jest, postcss, tailwind); в браузерный бандл не попадает ни одного уязвимого пакета.
- **Заголовки.** HSTS, CSP с nonce, `frame-ancestors`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`. CORS не отдаёт данные чужим сайтам.
- **Подбор пароля.** После 5 неверных попыток — 429 (блокировка хранится в `login_attempts`).
- **Логи.** Секреты (пароли, мнемоника, токены) в логи не пишутся; коды 2FA в логе бота маскируются.
- **Загрузки.** Лимит 5 МБ, имя файла очищается от путей.

## Рекомендации (за владельцем)
1. На бою: `ENV=production`, новые `ADMIN_SECRET`, `JWT_SECRET_KEY`, пароль админа — старые значения есть в истории git.
2. Ключи `PII_ENC_KEY`, `PII_INDEX_KEY`, `BACKUP_KEY` — хранить копию вне сервера (менеджер паролей / офлайн).
3. Шифрование диска сервера (LUKS / зашифрованный том хостинга).
4. CSP: в `script-src` есть `'unsafe-inline'` (современные браузеры его игнорируют при наличии nonce) — убрать после проверки, что все встроенные скрипты имеют nonce.
5. Перевести старые ссылки на владельца (`businesses.owner`, лоты) с кошелька/почты на id — тогда личные данные не останутся открытыми в этих записях.
6. Независимый аудит смарт-контракта FundDistributor перед запуском денег.

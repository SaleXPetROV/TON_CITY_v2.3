# Объявления (админка → Объявления)

## Кому уходит
- **Telegram** — всем, кто запускал бота (`telegram_mappings`), и всем аккаунтам с привязанным Telegram (`users.telegram_chat_id`). Один чат получает одно сообщение. Язык: язык бота → язык профиля → язык Telegram → en.
- **Канал** (Промо → Телеграм бот → «Канал») — один пост, всегда на английском.
- **В игре** — уведомление каждому аккаунту проекта.

## Скорость
| Что | По умолчанию | Настройка в `backend/.env` |
|---|---|---|
| Уведомления в игре | 50 в секунду | `ANNOUNCEMENT_INAPP_PER_SEC` |
| Сообщения в Telegram | 25 в секунду (максимум 30 — лимит Telegram для бота) | `BROADCAST_TG_PER_SEC` (старое `BROADCAST_RATE_PER_MIN` — «в минуту» — больше не используется) |

Обе доставки идут одновременно и независимо: уведомления в игре начинаются сразу, даже если Telegram отвечает медленно. Пост в канал публикуется в начале Telegram-части. Одному чату даётся не больше 60 с на все попытки, посту в канал — 90 с.

Кнопка «Остановить» в окне рассылки останавливает её в течение секунды (кто уже получил — получил). Если Telegram отвечает ошибкой, её текст виден в окне («ответ Telegram: …»).

## Окно рассылки
После «Опубликовать» открывается окно «Рассылка объявления»:
- «Пользователи бота (Telegram)»: отправлено X из Y, сколько заблокировали бота / чат не найден / ошибки, опубликовано ли в канал;
- «Пользователи проекта (в игре)»: получили X из Y;
- проценты, скорость и сколько осталось.

Окно можно закрыть — рассылка продолжится. Открыть снова: «Подробнее» в карточке объявления.
Данные: `GET /api/admin/announcement/{id}/delivery` (обновляется раз в секунду). Если сервер перезапустился во время рассылки, статус станет «прервана».

## Картинка
Загруженная картинка сохраняется файлом `backend/uploads/announcements/` и отдаётся по `/api/media/announcements/<имя>`.
В объявлении и в уведомлениях хранится только короткая ссылка. В Telegram картинка загружается **один раз**, остальным
получателям уходит её номер в Telegram (file_id). Старые объявления с картинкой внутри (data:) переводятся в файлы при запуске сервера.
Папку `backend/uploads/` (там же скины) нужно сохранять при обновлениях сервера.

## Одна рассылка за раз
Блокировка хранится в базе (`admin_settings`, `type: broadcast_lock`) и действует для всех процессов сервера. Повторное
«Опубликовать» во время рассылки → «Рассылка уже выполняется». Отложенные объявления ждут, пока закончится текущая.
Блокировка продлевается каждую секунду и сама освобождается через 2 минуты, если сервер упал.

## Если сервер не достаёт до api.telegram.org
Зеркало Bot API на Cloudflare Workers: код — `deploy/cloudflare-telegram-worker.js`.
1. Cloudflare → Workers & Pages → Create → Worker → Deploy → Edit code → вставить код → Deploy.
2. В коде можно указать `ALLOWED_BOT_ID` — цифры до «:» в токене бота (тогда зеркалом пользуется только ваш бот).
3. Проверка в браузере: `https://<имя>.<аккаунт>.workers.dev/bot<ТОКЕН>/getMe` → `{"ok":true,…}`.
4. В `backend/.env`: `TELEGRAM_API_BASE=https://<имя>.<аккаунт>.workers.dev` (без «/» в конце), `TELEGRAM_PROXY_URL` — убрать. Перезапустить сервер.
Все обращения к Telegram в коде идут через `TELEGRAM_API_BASE` (отправка, картинки, файлы, вебхук, проверка бота).

# Карта города: участки, покупка, восстановление

## Одна запись на участок
У каждого участка новой карты одна запись `plots` с id `city_v1-<номер слота>` (свободная — `owner: null`). Покупка (`/api/island/buy`) занимает именно эту запись, а бизнес получает `city_slot_id`, `city_island_id: "city_v1"`, `district_id`, `footprint`. Раньше покупка добавляла вторую запись рядом со свободной: карта показывала владельца, а окно участка — «Доступно» и «Купить» (и после нажатия пропадала метка «★ Вы»). Код: `core/plots.py` (выбор записи, удаление свободных двойников при старте).

## Ошибка с повторной миграцией (исправлено)
`city_switch.needs_switch` считал «старой картой» любой бизнес без `city_slot_id`, а покупка это поле не ставила. Поэтому после каждой покупки при следующем запуске сервера (или новом процессе) миграция запускалась заново и:
- переносила только что купленные бизнесы на другие участки (иногда на занятые);
- удаляла все записи участков и восстанавливала владельцев только у перенесённых — у остальных игроков участки становились «свободными».

Теперь миграция запускается только со старой карты. Скрипт миграции при ручном запуске не трогает занятые участки и сохраняет владельцев.

## Восстановление при старте (`city_repair.py`)
Без участия админа, повторно безопасно:
1. Бизнесы, перенесённые ошибочным повторным запуском, возвращаются на участок, где их купили (по резервной копии `migration_backup_<время>` того запуска), если он свободен.
2. Бизнесы без слота привязываются к слоту по своим координатам.
3. Записи участков следуют за бизнесами: владелец возвращается, участок ушедшего бизнеса освобождается.

Итог пишется в `admin_settings` (`type: city_map_repair`); участки, на которые претендуют два бизнеса, перечислены в `conflicts` — их нужно решить вручную. Тесты: `backend/tests/test_city_repair.py`.

## Id бизнесов
У каждого бизнеса свой `id` (UUID), участок ссылается на него через `business_id`. При старте бизнесу без id выдаётся id, а индекс `businesses.id` делается уникальным (`core/plots.ensure_business_ids`).

## Пресейл по районам
Админка → «Данные» → «Пресейл»: выберите карту, затем район. В таблице — все виды бизнесов этого района: сколько их в районе, сколько продано, сколько уже в пресейле, «Выставлю» (вводится в таблице) и сколько останется свободных. Так настраивается каждый район, затем «Выбрать поля» (поля выбираются случайно внутри своего района) и «Утвердить». Там же переключатель «Район открыт»: закрытый район затемнён, купить в нём нельзя.

Купить можно только поле пресейла (админ — любое). Старое ограничение «мест в продаже» по району убрано: раньше оно вместе с пресейлом блокировало покупку (при 0 мест поля пресейла нельзя было купить). На карте цена показывается только у полей пресейла.

API: `GET /api/admin/presale/inventory` (+ `by_district`, `districts`), `POST /api/admin/presale/select-plots` (строки `{district, type, count}`).

## Картинки 2-го эшелона на участках 2×2
ИИ-лаборатория, Фабрика чипов, Логистический хаб и NFT-студия стоят на участках 2×2 и рисуются квадратными зданиями 2×2 (пак скинов v3, `frontend/public/sprites/city/<тип>/stage1–3.webp`, `manifest.json`). Кибер-кафе, Ремзона и VR-клуб — на участках 1×2/2×1 со своими картинками 1×2. Если в админке («Скины» → спрайты на карте) для этих четырёх типов раньше загружалась своя картинка или менялся масштаб, она по-прежнему перекрывает новую — сбросьте её там.

## Скины групп (Crazy и другие)
Админка → «Скины»: у каждой группы тот же редактор, что у «Стандарта» — список бизнесов слева, участок и «На карте» с живым предпросмотром, ползунки (масштаб, ширина, высота, сдвиги) с кнопками −/+ по 1 %, «Сохранить для стадии» / «Применить ко всем стадиям», загрузка и удаление картинки для стадии. Настройки хранятся в `business_skins.tune`, карта игроков их применяет (`/api/skins/index` → `meta.tune`). API: `PUT /api/admin/skins/tune`, `DELETE /api/admin/skins/tune/{group}/{type}/{stage}`.

## Кибер-кафе, Ремзона, VR-клуб: участки 1×2 и 2×1
- У этих трёх бизнесов два вида: **«Вид 1×2»** (здание вытянуто вдоль участка 1×2) и **«Вид 2×1»** (вдоль участка 2×1). У каждого вида своя картинка и свои ползунки (`tuning` / `tuning_alt`; у групп скинов `image`/`tune` и `image_alt`/`tune_alt`).
- Админка → Скины → бизнес → кнопки «Вид 1×2 / Вид 2×1» сверху: ползунки и загрузка относятся к выбранному виду. В группе без своей картинки 2×1 показывается картинка 1×2, отражённая.
- Блок «Это место на карте»: для места, выбранного стрелками в «На карте», можно выбрать «Авто» (вид по форме участка), «Вид 1×2», «Вид 2×1» и «Отразить ↔». «Сохранить для этого места» → `admin_settings.city_sprites.slot_views[slot_id] = {view, mirror}`. Настройка места одна для стандартного спрайта и всех групп скинов.
- Отражение переворачивает и надписи на здании, поэтому для чистого вида лучше загрузить свою картинку 2×1.
- API: `PUT /api/admin/city-sprites/slot-view {slot_id, view: auto|main|alt, mirror}`, `DELETE /api/admin/city-sprites/slot-view/{slot_id}`, `PUT /api/admin/city-sprites/tuning {…, view: main|alt}`, `POST /api/admin/skins/upload` с `view=alt`.
